# 时段权益目录

这里保存实际计费渠道公开的、随政策时间变化的通用语言模型及相关套餐权益。通用文本／代码生成与推理模型即使具备多模态能力仍可收录；直接降低其使用成本或增加额度的编码、Token、Agent 等套餐也可收录，包括同时支持媒体模型的整套餐优惠。专用图像／视频／音频生成模型、结构化决策模型，以及独立的工具、安全、会话运行时服务不在范围内；不为这些对象新增权益或 Schema 表达能力。目录是有出处的结构化政策索引，不是完整条款、个人资格判断或实际账单保证。正式收录以 `benefits/` 中的数据 JSON 为准；测试示例不代表现行优惠。

## 文件与来源

- `channels/<渠道 ID>.json`：一个实际计费渠道及其计费服务商。当前没有已记录权益时也可保留渠道；渠道身份的公开出处保存在本文件。
- `benefits/<渠道 ID>/<权益 ID>.json`：一项可独立判断的政策规则。`accessChannelId`、`id` 须与路径一致；本文件的 `sourceReferences` 直接指向支持该规则的实际计费方公开条款。
- `discovery.json`：反复调查的官方入口，只是发现线索，不能代替权益证据；仍需搜索更广的一手来源。

各文件遵循 `schema/` 中同名 JSON Schema 的版本与字段约束；字段旁的 `description` 说明录入语义。按实际计费渠道归属，不按模型研发方归属：Qoder CN 使用 Qwen 模型，不意味着 Qoder 的活动属于阿里云百炼直连渠道。第三方资料只能用于发现，正式目录中的政策及具体主张须有实际计费方公开资料支持；领域数据不对来源打权威性分数。

稳定 ID 只用于文件身份和跨文件引用：权益引用的渠道及其他权益必须存在。计费方、模型、来源章节、日历例外和发现入口不另建 ID；发现入口按 URL 去重。

## 录入边界

一份权益文件对应一项可求值规则，不按营销页面合并。全部计费项应共享同一政策触发事件，所有列出的资格组合应共享同一实际效果；套餐、计费项或事件改变效果时拆文件。保留来源对应的模型、套餐、计费项、计价单位等简短原名，但不要在这些名称中写条件句。权益标题由消费端从结构化事实生成，JSON 不保存营销标题或通用备注。

`model` 条件只记录该渠道的**优惠适用条款直接列明**的模型称谓或 Model ID；一项优惠直接列出多个 ID 时全部保留，不建立跨渠道统一模型 ID。其他说明中的旧 ID 路由、兼容或版本映射不自动扩充优惠名单；关系未被结构化证实时，按另一调用 ID 查询不能因字符串不相同就断言权益不适用。模型名称与 ID 的详细关系仍由官方原文承担。

`eligibilityConditions` 限定本记录已核实的模型、计费项、套餐、工具、地域、客户端、账户类型、计费模式或服务端点等公共使用情形。可以只收录能独立证实的子范围，例如月付明确而年付冲突时只保留月付；未匹配只表示未命中收录范围，不能推导官方明确不适用。影响全部情形的必要限制无法确认时暂不收录；不能通过省略条件或减少 `none_of` 排除值扩大范围。全部条件匹配或数组为空也不证明某个账户最终适用。首次付费历史、订阅状态、实际发放、余额等个人事实留给原文和账户系统，不转成任意文本谓词。

`service_endpoint` 使用渠道公开且足以界定优惠范围的端点名称或标识。同渠道同模型的不同端点可以分别有权益；宽泛 Provider 名称或基础路由 slug 不自动等于精确端点。这里不建立端点注册表、别名或层级匹配，也不模拟路由与回退；未提供端点不能理解成所有请求均适用。

时间窗口只约束 `timeTrigger.kind` 指明的政策事件；类别可为模型请求、支付、领取、工具调用、持续计量、出账、订阅下单或 `unknown`。出账事件仅用于明确按出账时间判断的单项权益，不代表整个渠道如此判价；订阅下单不等于付款，类别已知也不等于判价瞬间已知。仅当计费方明确说明渠道通用的具体判价时刻时，才在渠道中填写 `billingDecisionInstant`。支付／领取窗口不等于取得后个人奖励的可用期；后者取决于账户事实，不进入目录。累计优惠用量上限等无法由静态目录求值的限制留在来源原文中；命中政策窗口不保证实际享受折扣，也不在 JSON 中另写原文转述。

尽量保留已知时间部分：每日或每周重复规则用 `recurring`，`weekdays` 是 ISO 星期数（周一为 1），跨午夜窗口归属开始日期，全天为 `00:00–24:00`。只公布开始日期、不公布该日小时的重复规则用 `validFromDate`，不能倒推首日全天适用；没有公布终止日期就不填 `validUntil`，但缺省不承诺永久有效。精确绝对边界用 `absolute`；仅公布日期而时区未知时用带 `role` 的 `knownBoundaries`，不得伪造 UTC 瞬间。已知结束时点但包含性未公布时，用 `endInclusive: null` 和 `endPrecision`。只有没有可用窗口时才用时间 `unresolved`；效果未知只影响 `effect`。法定假日等例外只填官方日历已覆盖的年份；未知年份的相关时段不能假定为普通工作日。

效果优先保存官方实际优惠单价或额度 `unit_rate`；可靠通常值才填 `regular`。通常值缺失时不能推算节省额、倍数或价格方向。仅当一个实际倍数对文件中所有情形精确成立时才用 `multiplier`；宣传月价不能替代按剩余时长折算的订单实付，无法得出统一效果时保持 `unresolved`。不同渠道同名单位不自动等价。重叠权益只有在官方明确说明且另一端已收录时才填写 `combinationRelations`；缺省不等于可叠加。

## 证据准入与退出

政策已证实、只是公开资料没有给全时间或统一可计算效果时，保留已知事实和上述局部未知。无法确认政策存在或必要公共适用范围时暂不收录，不能用未知效果掩盖证据缺口。来源只有 URL 还不够，原文须支持本记录的具体字段；同页其他活动的日期、渠道全部支持模型或宣传标价不能替代对应条款。

未核实新增从草案排除。撤销无依据修改前，先确认旧内容仍获来源支持；旧事实已被推翻，或重试及替代官方资料后仍无法复核时，删除或用可靠记录替代，不简单恢复 `main`。按证据撤出接受覆盖率降低，删除不证明官方活动已结束。PR 须区分三类理由：**活动结束、范围外、未满足证据准入**，逐项附来源及判断过程。搜索摘要、截断页面或单次访问失败本身都不证明政策结束。

每轮维护检查完整候选目录中的结束边界，包括本次没有修改的权益。时间事实足以证明结束时，核对是否有官方延期，再修正或删除；不得为通过检查随意移除或延后截止。截止精度、包含性或时区仍有歧义时保守判断，不补造时刻；领取后个人有效期不参与政策到期检查。

删除后检查跨文件引用；最后一项权益删除后，范围内的渠道仍可保留。首版不提供历史政策查询，旧内容由 Git 保存。核对无变化时不改文件，不维护逐条核验时间、核验年龄或手工递增版本；运行报告记录实际核对快照与范围，Git 提交时间不代表来源核验时间。

范围内活动有已核实的最小结构事实、但 Schema 无法忠实保存时，使用「规则表达能力缺口」GitHub Issue，附官方来源、具体字段阻碍及最小反例。允许的局部未知、访问失败或证据不足不是表达缺口。若新证据同时推翻旧记录，另提只改数据的保护性 PR，删除不再满足准入的旧权益或保留可靠子范围。数据 PR 不扩展 Schema，也不另造文本逃生口。

## 检查与提交

根目录的 `pnpm validate:catalog` 检查 JSON、路径、跨文件引用和可机械验证的业务不变量；默认结构检查不随系统时间变化。维护发布另外以明确判断时点检查完整候选目录中的确定过期记录。这些检查不抓网页，也不能证明来源支持具体主张或某账户最终适用。PR 正文逐项列出变更字段、官方 URL、支持该字段的页面章节及撤出理由，不在数据中另造字段级证据 ID。

日常维护先读取最新 `main`、开放 PR 及独立审计反馈，优先修正已有问题，再复核来源并调查新活动。使用 `catalog-update/` 分支，只修改 `catalog/discovery.json`、`catalog/channels/*.json`、`catalog/benefits/<渠道 ID>/*.json`。尽量一次原子提交完整候选；推送自动触发 GitHub 上的 **Prepare Catalog Update**，校验范围、格式、目录及确定过期记录，并在必要时回写纯格式改动。准备成功后重新读取 head，再创建 PR；整个路径无需本地 Git、Node、pnpm 或手动派发工作流。数据和工程内容必须分 PR。

自动创建 PR／Issue 时主动填写模板，不能假定 API 会套用。PR 还需等待当前 head 的 **Validate Catalog**、**Catalog PR Scope** 和 **Root Check**；准备运行不能代替 PR 检查。格式提交改变 head 后需取得新检查，不能沿用旧成功结果。

独立审计先按差异和相邻规则列待证事实，再核对来源与 PR 说明；全部变更及完整目录的到期风险均需覆盖。审计者不改待批准数据，发现问题交下一轮维护修正。仅在无剩余错误、无未核实新增或改写主张、审计完整且最新快照的准备与 PR 检查成功时自动合并；认可的局部未知不阻止合并。审计记录固定 `main` 与 head SHA，合并前再次核对；任一变化都需重新核对受影响内容及检查。资料、写入或合并能力受限时如实报告，不把调查材料当成已发布数据。
